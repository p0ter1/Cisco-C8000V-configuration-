# Cisco C1111-4P: CUBE для SIP-транка Ростелекома и кластера CUCM

Конфигурация лежит в файле [`c1111-cube-rostelecom-cucm.cfg`](c1111-cube-rostelecom-cucm.cfg). Это Cisco C1111-4P (IOS-XE 17.12+) в роли CUBE между SIP-транком Ростелекома и кластером CUCM. Конфигурация построена на тенантах (`voice class tenant`) и группах dial-peer (`voice class dpg`), WAN и LAN разнесены по разным VRF.

| Сторона | Подключение | Транспорт | VRF |
|---|---|---|---|
| Ростелеком | Регистрация с логином и паролем, SBC `95.167.123.123`, realm `123456.78.rt.ru` | UDP/5060 | `INET-PUBLIC1` |
| CUCM | Subscriber `10.97.0.146` (основной), Publisher `10.97.0.145` (резерв) | TCP/5060 | `VoIP` |

```
  РТ SBC                     Gi0/0/0                 Gi0/0/1                     CUCM SUB 10.97.0.146
  95.167.123.123 ──UDP 5060── 123.45.68.97 [ C1111 ] 10.50.51.62 ──TCP 5060── CUCM PUB 10.97.0.145
                          VRF INET-PUBLIC1            VRF VoIP
```

## Номера

| Городской номер (DID) | Внутренний номер |
|---|---|
| 3521234567 (основной, логин SIP) | 2030 |
| 3521234568 | 2031 |
| 3521234569 | 2032 |

Исходящий вызов с 2030, 2031 и 2032 уходит со своим городским номером. С любого другого внутреннего номера уходит основной 3521234567.

## Что заменить перед применением

| Параметр | В файле | Комментарий |
|---|---|---|
| Пароль SIP | `<SIP-ПАРОЛЬ>` | Репозиторий публичный, поэтому пароля в нём нет |
| Пароли администратора | `<ПАРОЛЬ>` | `username`, `enable` |
| Шлюз LAN к CUCM | `10.50.51.33` | В исходных данных не указан, поставлено предположение |
| Мастер-ключ шифрования | — | `key config-key password-encrypt <ключ>` вводится вручную до применения |

> **Пароль начинается с `!`.** При вставке конфигурации из файла IOS может принять строку с паролем за комментарий. Если после применения `show run | section tenant 100` не показывает строки `credentials` и `authentication`, введите их вручную в `configure terminal`. После `password encryption aes` пароль хранится в зашифрованном виде (type 6).

## Объекты конфигурации

| Объект | Ростелеком | CUCM |
|---|---|---|
| Тенант | `tenant 100`: Gi0/0/0, регистрация, учётные данные | `tenant 200`: Gi0/0/1 |
| Распознавание входящих | `uri 100` (Via от SBC) | `uri 200` (Via от PUB или SUB) |
| Исходящий dial-peer | `100` → `sip-server` | `200` → `server-group 200` |
| Входящий dial-peer | `101` → `dpg 200` | `201` → `dpg 100` |
| SIP-профиль | `100` исходящий, `101` входящий | — |
| Преобразование номеров | `TP-TO-RT`, `TP-FROM-RT` | — |

Экстренные вызовы (112, 101–104, 01–04, 911) от CUCM распознаются по Request-URI (`uri 110`). Они принимаются dial-peer 202 и уходят через `dpg 110` на dial-peer 110. Номера 01–04 преобразуются в 101–104, 911 — в 112.

## Как это работает

**Регистрация.** CUBE регистрируется на SBC Ростелекома как `3521234567` в домене `123456.78.rt.ru`. Логин, пароль и realm заданы в `tenant 100`. Ответ на запрос авторизации (401/407) формируется для REGISTER и для INVITE.

**Домен вместо IP.** Ростелеком обычно требует в Request-URI и To домен realm, а не IP SBC. SIP-профиль 100 заменяет `@95.167.123.123` на `@123456.78.rt.ru`, а `localhost` задаёт этот же домен в From.

**Входящий вызов (РТ → CUCM).** Все три номера обслуживаются одной учётной записью. Поэтому Ростелеком отправляет INVITE на зарегистрированный Contact `3521234567`, а набранный номер передаёт в заголовке To. Входящий SIP-профиль 101 копирует номер из To в Request-URI. Затем `TP-FROM-RT` заменяет городской номер внутренним (2030, 2031 или 2032), номер звонящего приводит к `+7XXXXXXXXXX`, и вызов уходит на CUCM: сначала на Subscriber, при его отказе — на Publisher.

**Исходящий вызов (CUCM → РТ).** Вызов от любой ноды CUCM уходит в Ростелеком. Набранный номер приводится к виду `8XXXXXXXXXX` (международные — `810…`), АОН подставляется по таблице номеров выше.

**Безопасность.** SIP принимается только от SBC Ростелекома и нод CUCM (`ip address trusted list`, `silent-discard untrusted`). ACL на Gi0/0/0 пропускает только SIP и RTP от SBC. Внутренние адреса скрыты (`address-hiding`), служебные заголовки Cisco удаляются.

**Кодеки.** На C1111-4P нет DSP, поэтому транскодирования нет. Обе стороны должны договориться о G.711 A-law (или G.711 µ-law / G.729 из списка). DTMF передаётся по RFC 2833, факс — по T.38 с переходом на G.711.

## Настройки на стороне CUCM

1. **SIP Trunk** к CUBE: Destination `10.50.51.62`, порт 5060, транспорт TCP.
2. Device Pool с Call Manager Group, где есть обе ноды; **Run on all Active Unified CM Nodes** — включено.
3. SIP Profile: включён OPTIONS Ping; MTP Required — выключено; DTMF — RFC 2833 или No Preference.
4. Significant Digits — `All`. Входящий вызов приходит на CUCM уже с внутренним номером 2030–2032.
5. Route Pattern в город направьте на транк. АОН можно передавать внутренним номером: CUBE сам заменит его на городской.
6. Экстренные номера: партиция `PT-Emergency` во всех CSS телефонов, Route Pattern `112`, `101`–`104`, `01`–`04`, `911` с **Urgent Priority**.

## Применение

1. Введите мастер-ключ: `key config-key password-encrypt <ключ>`.
2. Примените VRF, интерфейсы и маршруты.
3. Примените `voice service voip`, все `voice class`, преобразования номеров и dial-peer.
4. Проверьте, что пароль SIP принят (см. предупреждение выше).
5. Последним включите ACL на Gi0/0/0 (`ip access-group ACL-WAN-IN in`).
6. `write memory`.

> **Важно.** При назначении `vrf forwarding` IP-адрес интерфейса удаляется. Поэтому в конфигурации `vrf forwarding` идёт перед `ip address`. Не меняйте VRF на интерфейсе, через который вы подключены.

## Если не работает

| Симптом | Что проверить |
|---|---|
| Регистрация не проходит, 403 | Логин, пароль, realm. Ожидает ли РТ домен в Request-URI REGISTER (правило 10 профиля 100) |
| Регистрация не проходит, нет ответа | Маршрут в VRF `INET-PUBLIC1`, ACL на Gi0/0/0, `show sip-ua register status` |
| Все входящие попадают на 2030 | РТ передаёт номер не в To, а, например, в Diversion или P-Called-Party-ID. Поправьте профиль 101 по `debug ccsip messages` |
| Входящий не находит dial-peer 101 | Via приходит не с `95.167.123.123`: добавьте фактический адрес в `uri 100` и trusted list |
| Исходящий отбивается 403/404 | Формат номера (8 / 7 / без префикса), АОН вне группы номеров. В крайнем случае подставляйте всем `3521234567` |
| Нет звука | Медиа РТ идёт с другого адреса: добавьте его подсеть в ACL-WAN-IN (строка 20) |

## Вопросы к Ростелекому

- формат вызываемого номера (10 или 11 цифр, `8` или `7`, международные);
- можно ли передавать в From или PAI номера 3521234568 и 3521234569;
- в каком заголовке приходит набранный номер на входящих;
- адреса SBC для медиа;
- поддержка T.38;
- формат экстренных номеров и адрес для службы 112.
