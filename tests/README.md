# Офлайн-тесты конфигураций

Тесты проверяют логику конфигураций CUBE без маршрутизатора. Нужен только Python 3.10+, сторонних зависимостей нет.

```
python3 -m unittest discover -s tests -v
```

Тесты запускаются автоматически в GitHub Actions при каждом push и pull request (`.github/workflows/config-tests.yml`).

## Что проверяется

| Файл | Что проверяет |
|---|---|
| `test_common.py` | Общие проверки для **каждого** `*.cfg` в репозитории (новый файл подхватывается автоматически) |
| `test_c1111_rostelecom.py` | Сценарии вызовов C1111-4P + Ростелеком |
| `test_c8000v_mts.py` | Сценарии вызовов C8000V + МТС |
| `ios_model.py` | Разбор конфигурации и эмуляция логики IOS-XE |

**Общие проверки:**
- все ссылки dial-peer существуют: tenant, dpg, uri, server-group, keepalive, codec, translation-profile, sip-profiles;
- в dpg только исходящие dial-peer, у каждого входящего есть `destination dpg`, вызов всегда переходит на другую сторону CUBE;
- интерфейсы тенантов существуют и имеют IP, control и media на одном интерфейсе;
- транспорт OPTIONS keepalive совпадает с транспортом dial-peer;
- каждый адрес сигнализации (server-group, uri, registrar) есть в `ip address trusted list`, в списке нет широких сетей;
- WAN ACL пропускает SIP от каждого публичного доверенного адреса и заканчивается `deny`;
- в конфигурации нет паролей в открытом виде, только подстановки `<...>`;
- next-hop статических маршрутов находится в подключённой сети того же VRF.

**Сценарии вызовов** моделируют путь вызова: входящий dial-peer → преобразование номеров → dpg → исходящий dial-peer. Проверяется, какие dial-peer выбраны и какие номера уходят на выходе. Для Ростелекома дополнительно проверяются SIP-профили на примерах REGISTER и INVITE: домен realm вместо IP SBC, удаление заголовков Cisco, перенос DID из To в Request-URI.

## Чего тесты не проверяют

- **Синтаксис команд IOS-XE.** Модель не знает, примет ли маршрутизатор команду. Опечатку в ключевом слове поймает только реальный IOS.
- **Поведение на железе:** регистрацию, VRF-aware CUBE, обработку SIP-профилей в конкретной версии ПО, медиа.

Модель следует документированной логике IOS-XE с упрощениями:
- входящий dial-peer выбирается сначала по Request-URI, затем по Via;
- правила `voice translation-rule` проверяются по возрастанию номера, срабатывает первое совпавшее;
- входящий SIP-профиль применяется до определения вызываемого номера.

Финальная проверка — на стенде: Cisco Modeling Labs, C8000V на своём гипервизоре или запасной маршрутизатор. Виртуального образа C1111 нет, поэтому конфигурацию Ростелекома можно проверить на C8000V, заменив имена интерфейсов.
